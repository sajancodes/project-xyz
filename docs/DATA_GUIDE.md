# DATA GUIDE

Every type of training data in Project XYZ, its purpose, examples, and risks.

## 1. FineWeb (general language)

- **Purpose**: teach English fluency, grammar, factual-statistical patterns.
- **Source**: HuggingFaceFW/fineweb, CC-MAIN-2025-26, streamed.
- **Used in**: pretraining; 90% of old mixed runs; 10% of SEMV2E batches (preservation share).
- **Validation**: a held-out FineWeb window (42,312 tokens) is used ONLY to monitor regression.
- **Risk**: pure next-token data teaches fluency, not task behavior; used alone it recovers weak factual QA.

## 2. Synthetic semantic data (question/answer)

- **Purpose**: teach question-answering behavior (eventually through `User:`/`Assistant:` wrapped rows).
- **Evolution**:
  - 41 fixed examples (exp 1) — taught facts but caused catastrophic forgetting (grammar 55.6→33.3).
  - Procedural generator `src/utils/semantic_data.py` (SEMV2+) — unique examples per draw.
  - SEMV2E `src/utils/semv2e_data.py` — leakage-safe binding data.
- **Risk**: if data is fixed or repeated, the model memorizes strings instead of generalizing.

## 3. Alpaca instruction data

- **Purpose**: instruction following.
- **Source**: yahma/alpaca-cleaned (8,000 examples used in SEMV2E; subset loaded in SEMV2).
- **Format**: instruction + input + output, wrapped as User/Assistant.
- **Risk**: model depends on the chat wrapper (plain-QA scores drop from 43.2% to 25.8% on the binding benchmark).

## 4. Binding data (SEMV2E, the current focus)

Categories generated by `src/utils/semv2e_data.py` (weights in parentheses):

| Category | Training weight | Example |
|---|---|---|
| single_fact (14) | teach one-fact retrieval | "Aaron owns a red car. What does Aaron own?" → a red car |
| multi_fact (14) | choose the right fact among two | two owners, ask about one |
| distractor (12) | ignore noise facts | three owners + distractor sentence |
| relation_reversal (12) | answer the direction reversed | "Who owns the car?" |
| paraphrase (12) | different wording same meaning | possesses/has/owns; "What does X have?" |
| pronoun (10) | resolve he/she/their | "She parked it outside. What color is her car?" |
| multi_hop (10) | chain two facts | owns a car; the car is blue → color |
| sentence_order (8) | facts re-ordered | property first, owner second |
| generalization (8) | fresh objects/verbs | unseen-combination questions |
| negation (6) | "does not" | "Aaron does not own a car. Does he?" → no |
| contrastive_binding (12) | bind each entity to its own fact | "What color is B's car?" under competition |
| location_state (6) | where-parked state | "Where did X park?" |

- Example format: `User: <context + question>\nAssistant: <answer>`.
- **Leakage safety**: training names (Aaron, Bella, Caleb, ...) are DISJOINT from benchmark names (Maya, Ravi, Sita, ...). An overlap guard raises a hard error. Runtime assertion in the trainer.

## 5. Arithmetic data

- **Purpose**: controlled secondary experiment (not yet successful).
- **Volume**: 1,000 examples in SEMV2E; 5% of each batch.
- **Result to date**: arithmetic is **0%** on every benchmark protocol and scale tested. We record this honestly as a fact; we do not claim a capacity limit without further controlled experiments.

## 6. Sun / world-knowledge data

- **Purpose**: teach sunrise→east and sunset→west with BALANCED, paraphrased coverage.
- **Historical problem**: the model knows "sun rises in east" (62.5%) but not "sun sets west" (12.5%) — strong evidence of template overfitting from earlier data that repeated one phrasing.

## 7. The semantic-vs-memorization rules (the project's guardrails)

1. **Repeat no fixed string thousands of times.** Templates must vary names, objects, colors, relations, structures, wording, order, length.
2. **Generate underlying facts and MULTIPLE surface realizations** — e.g. owns/has/possesses/keeps; "What does X own?/have/possess?"; "Who owns the X?/Whose X is it?".
3. **Hold out entities/templates** — SEMV2E training names are disjoint from benchmark names; the benchmark JSON is evaluation-only.
4. **TRAINING DATA MUST NEVER CONTAIN THE HELD-OUT TEST EXAMPLES.**

## 8. Held-out benchmark data

- `data/semv2e_benchmark.json` — 600 questions, 10 categories (A–J), deterministic seed, names Maya/Ravi/Sita/Theo/... disjoint from training names. **Read-only; never opened by the trainer.**

## 9. Where data lives

| Path | Contents |
